## Нейминг и размер файлов

### Нейминг

1. Имя файла должно отражать суть содержимого — группа функций, связанных единым контекстом.
2. Формат: `snake_case`.
3. Имя не должно быть длинным. Если контекст укладывается в одно слово — использовать одно слово (`speech.rs`, `playback.rs`).
4. Для группы однотипных файлов (табы, вкладки, виджеты и т.п.): сначала идёт общий контекст, затем контекст специализации, через подчёркивание.
   - ✅ `tab_status.rs`, `tab_settings.rs`, `tab_logs.rs`
   - ❌ `status_tab.rs`, `settings_tab.rs`, `logs_tab.rs`
   - ✅ `audio/` подмодули: `tts.rs`, `speech.rs` (общий контекст — директория `audio/`)
   - ✅ Вспомогательные файлы: `tab_status_helpers.rs`, `mic_utils.rs`

### Уникальность имён файлов

1. Запрещены файлы-двойники с одинаковым именем (без учёта пути) во всём проекте.
2. Пример: в проекте не может быть двух файлов `audio.rs` или двух `helpers.rs` в разных папках — это создаёт путаницу.
3. Исключение: `mod.rs`, `main.rs`, `lib.rs` — служебные имена, продиктованные языком.
4. Если файл с нужным именем уже занят в другой папке — дать более конкретное имя, отражающее различие контекстов.

### Размер файлов

1. **Максимум по умолчанию:** 250 строк на файл.
2. **Допустимое превышение:** до 50% (т.е. до 375 строк), если:
   - контекст файла един и целостен,
   - код не подразумевает переиспользование из других мест проекта (внутренние хелперы используются только внутри этого файла),
   - и при этом **не** создаются вспомогательные файлы (`_helpers`, `_utils` и т.п.).
3. Если для файла понадобились вспомогательные файлы — правило +50% **не действует**: все файлы группы (основной + хелперы) должны быть ≤250 строк каждый.
4. Пример-исключение (без хелперов): `tab_status.rs` (285 строк) — целостный контекст отрисовки одной вкладки, нет смысла дробить.

### Механизм при превышении 375 строк

Если файл превышает 375 строк, но контекст един и не разбивается на переиспользуемые модули:

1. **Шаг 1 — выделение хелперов:** вынести чистые вспомогательные функции в соседний файл `{context}_helpers.rs` (например, `tab_status_helpers.rs`). После этого **все** файлы группы должны быть ≤250 строк.
2. **Шаг 2 — директория:** если после Шага 1 файл всё ещё > 250 строк, превратить его в директорию `{context}/`:
   - `{context}/mod.rs` — публичное API и реэкспорты
   - `{context}/render.rs` — отрисовка UI
   - `{context}/handlers.rs` — обработчики событий/команд
   - `{context}/helpers.rs` — внутренние утилиты
   - Naming подфайлов: сохраняется принцип `контекст_специализация` (контекст = родительская директория).
   - Каждый файл в директории — ≤250 строк.
3. **Шаг 3 — переиспользование:** если хелперы понадобились извне — переместить их на уровень выше (в модуль родителя), а в `{context}/` оставить только публичный реэкспорт.
